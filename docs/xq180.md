# XQ180 适配说明

当前 AMP 训练使用 `ampfix_v6`，修复归一化与梯度处理，并增加分阶段学习率及 KL 停止。旧 checkpoint 的训练迁移见 [修复与续训说明](xq180_amp_fix.md)。

资源来自 `/home/milkyway/opensource/hunter130_train/legged_lab/assets/xq180`，已复制到 `src/assets/robots/xq180/`。训练和回放不依赖外部资源目录。以下命令在仓库根目录、`conda activate mjlab` 后执行。

## 模型与控制

- 19 个活动关节：左右腿各 5 个（yaw、roll、pitch、knee、ankle pitch）、腰 yaw 1 个、左右臂各 4 个。20 个连杆，总质量 **66.609902 kg**。
- 保留 URDF 的 `base_link`、`waist_Link`、`waist_point`、`leftelbow_joint` 等原始名称和大小写。关节/执行器顺序为 URDF 深度优先顺序：左腿、右腿、腰、左臂、右臂；具体见 [接口参数](xq180_policy_io.json)。
- 名义站姿沿用来源配置：根高度 1.08 m，hip pitch -0.25、knee 0.5、ankle -0.25、shoulder pitch -0.1、elbow -0.5、左右 shoulder roll +0.15/-0.15 rad。足底 sites 初始离地约 35.77 mm，无初始自碰撞。
- 保留足部原始 STL，碰撞使用 MuJoCo 凸包；其余部位由原始网格范围拟合盒体或胶囊。沿用本项目相邻两级连杆的自碰撞排除方式，其余自碰撞启用。
- 原 URDF 的左肩 `left_shoulder_pitch_Link` 惯量违反三角不等式，MuJoCo 无法直接加载。**原 URDF 保持原值**；MJCF 生成器保留该连杆质量、质心、主轴及两个较小主惯量，把最大主惯量从约 `0.000473435730` 修正为 `0.999 * (I_min + I_mid)`，约 `0.000460103706 kg·m²`，0.1% 余量用于避免求解器舍入误差。MJCF 中有修正注释，其他连杆采用原完整惯量。这是 CAD 数据兼容修正，仍需用可靠物理参数复核。

PD 当前为 **`user_pd_v5`**，使用用户指定的整数表，左右相同；shoulder pitch 按 Kp=50、Kd=2 处理。训练配置见 [仅行走训练说明](xq180_locomotion.md)，此前 G1 构型推导参数保存在 [v4 快照](xq180_policy_io_g1_chain_v4.json)。

| 关节组 | Kp | Kd |
|---|---:|---:|
| hip yaw | 200 | 10 |
| hip roll | 400 | 20 |
| hip pitch | 300 | 15 |
| knee | 300 | 15 |
| ankle pitch | 100 | 5 |
| waist yaw | 100 | 5 |
| shoulder pitch | 50 | 2 |
| shoulder roll | 50 | 2 |
| shoulder yaw | 25 | 1 |
| elbow | 25 | 1 |

位置控制为 `q_target = q_default + action_scale * clip(action, -3, 3)`。新 scale 为 `min(0.25 * XQ180_effort / XQ180_Kp, G1_对应关节_scale)`，限制降低 Kp 后的探索幅度。armature 维持 0.01 kg·m²，URDF 力矩及速度参数保持原值。这是待训练对照的仿真初值，未完成实机辨识。

旧 PD 和旧 scale 保存在 [legacy 接口参数](xq180_policy_io_legacy.json)，配套已有旧 ONNX；新接口参数见 [当前 JSON](xq180_policy_io.json)。参数更改后应开启新训练，不能将旧模型与新控制参数直接混用。

## 任务与启动

已注册四个独立任务：`XQ180-Flat`、`XQ180-Rough`、`XQ180-AMP-Flat`、`XQ180-AMP-Rough`。

```bash
python scripts/list_envs.py --keyword XQ180
python scripts/play.py XQ180-Flat --agent zero --num-envs 1
python scripts/train.py XQ180-Flat --env.scene.num-envs=4096
python scripts/train.py XQ180-AMP-Flat --env.scene.num-envs=4096
```

普通速度任务日志在 `logs/rsl_rl/xq180_velocity_userpd_v5/`，AMP 在 `logs/rsl_rl/xq180_amp_locomotion_no_recovery_userpd_v5_ampfix_v6/`。AMP 控制频率 50 Hz，actor 使用 4 帧历史，Flat 输入 264 维、输出 19 维；身体观测选取 11 个实际连杆，以 `waist_Link` 为 anchor。普通速度任务及 Rough 的观测维度不同。新机器人须单独训练，不能直接加载 G1/Hunter 的策略权重。

## AMP 动作

已采用接触约束全身 IK，把 18 段 G1 数据（17 段走跑、1 段恢复，共 9992 帧、50 Hz）重定向到 `src/assets/motions/xq180/amp_ik/`。AMP 重置和判别器只使用其 `WalkandRun/` 子目录（17 段、7417 帧）；`Recovery/` 保留用于历史检查，已退出训练。跌倒立即重置，不训练爬起。旧关节映射数据保留在 `amp/` 作为对照。

新版处理足部支撑/枢转、目标结构可达范围、0.9 软限位和自碰撞，并从最终姿态重算 FK 与速度。逐帧检查中，reset 软限位偏差和 >1 mm 自穿透均为零；近地足底 site 移动速度代理均值下降约 38.6%。方法、逐段结果、姿态预览和实际限制见 [重定向文档](xq180_retarget.md)。

```bash
python scripts/play_motions.py --speed 0.5
python scripts/retarget_g1_to_xq180.py
python scripts/validate_xq180_ik.py
```

输入为 G1 原始 NPZ，转换器完成原关节名称映射和肘部固定旋转补偿。自备已重定向 CSV 时，`scripts/csv_to_npz.py --robot xq180` 可重算 FK；CSV 中的角度应已采用 XQ180 定义，勿重复减 π/2，输出应通过软限位/速度/碰撞检查后再加入训练库。

## 重建和验证

```bash
python scripts/convert_xq180.py
python -m unittest discover -s tests -v
python -m src.assets.robots.xq180.xq180_constants
```

`scene_xq180.xml` 可预览带地面模型；裸 MJCF 不含执行器，训练 Entity 注入 PD 执行器和名义站姿。`imu_in_pelvis` 是共享转换器保留的兼容 site 名，实际挂在 XQ180 的 `base_link`。

验证包含原始动力学及修正后的左肩惯量、关节坐标/限位、PD、足部网格、配置隔离、四个任务注册与转换动作的目标 FK 一致性。另使用 CPU 执行环境初始化、重置和有限步进；未进行 GPU 大规模训练或实机验证。当前接口 JSON 描述新的 AMP Flat 参数，需重新训练导出；旧模型核验记录在 legacy JSON 中。部署接口、完整关节参数、导出方法与推理示例见 [XQ180 神经网络部署文档](xq180_deployment.md)；尚未完成 ONNX Runtime 闭环或实机验证。
