# XQ180 动作质量与 G1 参考 PD 检查

> 本文为历史检查记录。当前采用仅行走、G1 惯量比例整数 PD，参数及命令以 [当前方案](xq180_locomotion.md) 为准。

检查日期：2026-10-20。后续已完成 [接触约束动作重定向](xq180_retarget.md)，当前训练使用 `amp_ik/`；本文以下动作缺陷统计针对保留的旧 `amp/` 对照库。本文记录此前 `g1_inertia_v1` 实验；当前配置已更新为 `leg_damping_v2`（见 [最新检查](xq180_motion_check.md)），见 [当前接口 JSON](xq180_policy_io.json)。下文 PD 数值、阶跃图和测试结果均属于历史 G1 参考方案。当前训练效果尚未收敛，逐帧检查确认参考动作中有结构适配问题；本次同时配置了 **`g1_inertia_v1`** PD，作为下一轮训练的对照起点。它尚未证明能改善训练收敛，原始 NPZ 仍有下述问题。

完整数据：[动作检查 JSON](xq180_audit/motion_audit.json)、[动作对比图](xq180_audit/motion_audit.png)、[PD 对比 JSON](xq180_audit/pd_comparison.json)、[PD 阶跃图](xq180_audit/pd_step_response.png)。

## 动作确实存在适配损失

对 18 段、9992 帧动作逐帧执行了目标模型 FK 和自碰撞检测，比较了源 G1 与目标 XQ180 的足底 site 运动及根部竖直加速度。源文件顺序、目标 FK 和速度数组一致性检查通过；主要问题是动作内容与目标结构不匹配。

| 项目 | 全部动作结果 |
|---|---:|
| 关节被硬限位裁剪的样本数 | 10870 个关节×帧样本 |
| 至少一个关节被硬限位裁剪的帧比例 | 42.57% |
| 至少一个关节在 reset 时还会被 0.9 软限位再次改变的帧比例 | 56.35% |
| 当前碰撞模型下，自穿透超过 1 mm 的帧比例 | 14.04% |

硬限位数据由 G1 名称映射、肘部固定旋转补偿后的角度与现有 NPZ 比较得到；不是 42.57% 的所有关节都错误。自碰撞统计使用训练所用的碰撞几何与排除规则，包含盒体/胶囊近似，表示该仿真碰撞模型中的构型冲突，不等价于实物 CAD 的精确干涉测量。

### 肘部和髋部限位

- `arc_jog_left_loop_002__A029`：左肘 94.5%、右肘 87.8% 的帧被裁到限位。XQ180 肘固定旋转 +π/2 的补偿公式本身正确，但其可达范围不能覆盖大量 G1 肘姿态，肘部轨迹因此长时间停在限位。
- `walk_sideway_left_loop_002__A021`：左右 hip roll 分别约 24.0%、17.4% 的帧被裁剪。两侧腿的关节排列、轴间偏移和可达范围都与 G1 不同，按名称直接复制角度无法保留原脚轨迹。
- 恢复动作中左右 hip roll 裁剪率约 31.5% / 42.3%，膝关节约 29.9% / 24.3%。缺少 ankle roll、waist roll/pitch 还会减少目标模型可重现的姿态自由度。

### 参考动作与 reset 不一致

离线转换按 URDF 硬限位裁剪，但 `MotionResetManager._write_reset_state()` 再把关节位置夹到 `soft_joint_pos_limits`。AMP 专家数据仍保留原始硬限位角度与速度，而环境起始位置已经变化，速度却仍来自原动作。

全库 56.35% 的帧受影响；恢复动作达到约 97.5%。这会使环境起始构型、速度与专家参考不一致，单纯调整 PD 无法消除这一偏差。动作重定向时应采用与 reset 一致的目标范围，并重新计算整套关节/连杆速度，或在明确验证后统一 reset 的限制策略。

### 足部运动与根部高度

| 片段 | G1 近地足底 site 水平速度均值 (m/s) | XQ180 同指标 (m/s) | G1 根部竖直加速度 P99 (m/s²) | XQ180 同指标 (m/s²) |
|---|---:|---:|---:|---:|
| arc_jog_left_loop_002__A029 | 0.388 | 0.866 | 13.35 | 33.16 |
| arc_walk_left_loop_001__A029 | 0.389 | 0.772 | 4.69 | 19.31 |
| walk_sideway_left_loop_002__A021 | 0.192 | 0.351 | 3.62 | 29.04 |
| walk_sideway_right_loop_001__A022 | 0.265 | 0.490 | 3.00 | 21.60 |

“近地”定义为足底 site 高度 `<35 mm`；水平速度由每帧 site 位置差分计算。它是运动学滑移代理，包含脚掌滚动和落地/抬脚阶段，并非仿真接触求解器测得的真实滑动速度。G1 原参考也并非完全无滑移，转换进一步放大了这个指标。

现有算法每帧用“全身最低碰撞体”修正根 Z，在支撑部位切换、裁剪或碰撞体极值切换时，可能增加高度导数变化；大幅竖直加速度意味着目标参考更难动态复现。上述比较显示它不只是模型自然变大后的平滑高度变化。

### 自碰撞

- `jog_forward_loop_003__A022` 约 46.5% 的帧有 >1 mm 自穿透，最深约 41.8 mm，主要是肘/前臂碰撞体与腰/根部。
- 右侧走片段约 19.7% 的帧有自穿透，涉及手臂与根部、左右脚和脚与对侧膝。
- 恢复片段约 32.6% 的帧有自穿透，最深约 82.4 mm。

这会使 AMP 要求的身体构型与碰撞求解器/自碰撞奖励冲突。恢复片段也不应仅以“成功生成 FK”作为数据可用的判据。

## 根据 G1 选择新的 PD

G1 总质量 33.341142 kg，XQ180 66.609902 kg，质量比约 1.998。两台机器人的负载分布、腿长和手臂惯量不同，因此采用按关节组的模型比较，而不是一个整机倍数。

在各自名义站姿下计算质量矩阵 M，把本侧足底六维速度约束为零，消去浮动基座速度：

```text
J_base * v_base + J_joint * dq = 0
T = [-inverse(J_base) * J_joint; Identity]
M_support = transpose(T) * M * T
ratio_i = diag(M_support_XQ180)_i / diag(M_support_G1)_mapped_i
```

该方法是单脚固定、其余关节速度为零时的局部惯量比较。它没有包含双支撑约束、整段运动中变化的耦合或已辨识的驱动器参数。计算出的左右侧比值与选定的对称倍数如下：

| 关节组 | 模型单支撑惯量比范围 | 选定 G1 Kp/Kd 倍数 | 新 Kp | 新 Kd | 旧 Kp/Kd |
|---|---:|---:|---:|---:|---|
| hip yaw | 2.28–2.33 | 2.5 | 100.4481 | 6.3947 | 300 / 20 |
| hip roll | 3.15–3.19 | 3.25 | 322.0699 | 20.5036 | 400 / 30 |
| hip pitch | 2.95–2.97 | 3.0 | 297.2953 | 18.9264 | 500 / 30 |
| knee | 3.10 | 3.1 | 307.2051 | 19.5573 | 500 / 30 |
| ankle pitch | 3.55 | 3.6 | 102.6045 | 6.5320 | 200 / 10 |
| waist yaw | 1.53 | 1.6 | 64.2868 | 4.0926 | 300 / 20 |
| shoulder / elbow | 0.45–0.87 | 2.0 | 28.5012 | 1.8144 | 100 / 10 |

Kp 单位 Nm/rad，Kd 单位 Nm·s/rad。腿和腰采用略向上取整的对称倍数；手臂采用 2 倍 G1，给重力负载和未建模驱动器留下保守刚度余量，这不是按手臂惯量比精确求得的最优值。

局部二阶近似下 `omega_n=sqrt(Kp/I)`、`zeta=Kd/(2*sqrt(Kp*I))`。当 I、Kp、Kd 同比例改变时，这两项保持一致，因此同时参考 G1 的 Kp 和 Kd 比单独调整 Kp 更有依据。对实际耦合系统仍需闭环验证。

该 G1 方案的完整精度参数保存在 [方案快照](xq180_policy_io_g1_inertia_v1.json)；[xq180_constants.py](../src/assets/robots/xq180/xq180_constants.py) 当前使用降低腿部阻尼后的表格。名义站姿、armature=0.01、URDF 力矩上限均保持原值。

### 动作缩放同步处理

降低 Kp 后，旧公式会把踝动作幅度扩大到约 1.01 rad/单位动作。现在使用：

```text
scale_XQ180 = min(0.25 * effort_XQ180 / Kp_XQ180,
                  0.25 * effort_G1 / Kp_G1)
```

新踝 scale 为约 0.438577，肩/肘约 0.315776；其余数值见 JSON。这是与 PD 一同发生的控制接口变化。比较新旧训练时应记录 PD 和 scale 两者，不能把训练结果的变化全部归因于 PD。

## 验证结果和实际限制

- 全部 20 项回归检查通过，包括旧 Hunter130/180 回归、G1 关节映射、PD 比例、动作幅度界限、力矩限幅与模型一致性。
- 四个 XQ180 任务均通过 CPU 初始化、reset 和 8 个有限步进，观测/奖励保持有限。
- 固定根、关闭重力和接触，对 8 个代表关节执行 0.08 rad 阶跃，比较 G1、旧 PD 与新 PD。新 hip pitch 上升到 90% 目标约 0.185 s，G1 约 0.180 s；新 knee 约 0.145 s，G1 约 0.140 s；新 elbow 约 0.130 s，旧值约 0.225 s。各测试末端误差趋近零，存在符合二阶系统特性的超调，并不代表所有关节响应都更优。
- 阶跃比较使用 MuJoCo builtin PD，没有执行 G1 自定义扭矩速度曲线/摩擦 compute，也不是策略跟踪测试。
- 另做了 3 s 的自由根、带地面、恒定名义目标测试；旧参数约 1.82 s、新参数约 1.65 s 触发高度/倾角跌倒阈值。两者均无法依靠固定关节目标维持平衡，**该测试没有证明新 PD 的站立稳定性改善**，只能确认数值有限。学习到的平衡反馈仍然必需。

读取本地旧 run 的 TensorBoard 时有 57269 条 iteration 记录。前/后各 100 条均值中，训练平均 reward 约从 -1.92 增至 31.24，平均 episode 长度从 118.8 增至 835.7 控制步，后者按 20 ms 折算约 16.7 s。这说明策略有明显学习进展；单凭这些统计无法确定未收敛的唯一原因，也无法直接比较不同命令课程阶段的速度误差。

## 下一轮训练和动作处理顺序

新实验目录为 `logs/rsl_rl/xq180_amp_locomotion_g1pd_v1/` 和 `logs/rsl_rl/xq180_velocity_g1pd_v1/`，避免自动选中旧控制参数的模型。启动新的对照训练：

```bash
conda activate mjlab
python scripts/train.py XQ180-AMP-Flat --env.scene.num-envs=4096
```

不要用旧 run 的 checkpoint 配新 PD/scale 直接评估改进。已有 ONNX 对应 [legacy 接口 JSON](xq180_policy_io_legacy.json)，新参数需重新训练、导出并评估。

动作侧优先进行与 5 自由度腿结构相符的、带支撑脚位置/姿态约束的重定向，统一 reset 与参考数据的限位，再处理手臂可达范围与自碰撞。重新求得 q 与根轨迹后，应重算全部 FK 和速度，并对走跑、恢复分别复查。当前参考 NPZ 未修改，因此本轮 PD 对照仍带有上述动作质量限制，不能视作完整的收敛问题修复。

重新生成本报告数据：

```bash
python scripts/analyze_xq180.py
python scripts/compare_xq180_pd.py \
  --current-io docs/xq180_policy_io_g1_inertia_v1.json \
  --output-dir docs/xq180_audit
python -m unittest discover -s tests -v
```
